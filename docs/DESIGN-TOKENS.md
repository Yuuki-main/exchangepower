# Design tokens

The visual system for the Exchange Power rebuild. All tokens live in **one place**: the `@theme` block in `src/app/globals.css`. Components only use token names, such as `bg-brand-700`, `text-foreground-muted` and `py-section`. They never use raw hex values or Tailwind's default palette, which is switched off with `--color-*: initial`.

> **Status:** proposed palette. The business hasn't confirmed brand colours or the logo yet (PLAN.md Part C, item 7). To rebrand, change the hex values in `globals.css`, run `npm run check:contrast`, and paste the new table below with `npm run check:contrast -- --md`.

### Colour rules

- **Amber (`accent-300` to `accent-500`) is for fills only on light backgrounds.** Never use it for text or meaningful icons on white, because it's only about 2.3:1. Use `accent-700` for amber icons on light surfaces. On dark surfaces, `accent-300` and `accent-400` are safe for text and icons.
- The primary button is amber with `brand-950` text, and works on both light and dark sections.
- **Focus ring:** a 3px outline using the `--ring` CSS variable, set globally on `:focus-visible` in `globals.css`. It's `brand-600` by default. `Section background="brand"` and `Card variant="inverse"` switch it to `accent-300`, and invalid inputs switch it to `error-600`.

## Typography

| Role                                | Font                                  | Loading                                                                           |
| ----------------------------------- | ------------------------------------- | --------------------------------------------------------------------------------- |
| Display / headings (`font-display`) | **Sora** (variable, weights 100–800)  | `next/font/google`, self-hosted, `display: "swap"`, CSS variable `--font-heading` |
| Body (`font-sans`, default)         | **Inter** (variable, weights 100–900) | `next/font/google`, self-hosted, `display: "swap"`, CSS variable `--font-body`    |

`next/font` serves both fonts from our own domain (no requests to Google), preloads the Latin subset, and generates size-matched fallback fonts. Swapping in the real font therefore causes almost no layout shift.

### Fluid type scale

Sizes scale smoothly from a **360px** viewport (minimum) to about **1440px** (maximum) using `clamp()`.

| Utility     | Min (360px) | Max (1440px) | Line height | Typical use               |
| ----------- | ----------- | ------------ | ----------- | ------------------------- |
| `text-xs`   | 12px        | 12px         | 1.5         | Badges, fine print        |
| `text-sm`   | 14px        | 14px         | 1.5         | Labels, hints             |
| `text-base` | 16px        | 16px         | 1.65        | Body                      |
| `text-lg`   | 17px        | 19px         | 1.6         | Lead text                 |
| `text-xl`   | 19px        | 23px         | 1.45        | Heading `sm`              |
| `text-2xl`  | 22px        | 30px         | 1.3         | Heading `md`              |
| `text-3xl`  | 26px        | 40px         | 1.2         | Heading `lg`              |
| `text-4xl`  | 32px        | 52px         | 1.12        | Heading `xl` (default h1) |
| `text-5xl`  | 38px        | 66px         | 1.05        | Heading `display` (hero)  |

Inputs are always 16px, so iOS Safari doesn't zoom in when a field gets focus.

Shadows are tinted with brand-900 rather than black, so they blend with the palette.

**Reduced motion:** when the user sets `prefers-reduced-motion: reduce`, a global rule in `globals.css` cuts every animation and transition to near zero and turns off smooth scrolling.

## Breakpoints

Mobile first. Base styles target phones, and prefixes add styles at the given **minimum** width. These are Tailwind's defaults, unchanged.

| Prefix | Min width | Typical device                     |
| ------ | --------- | ---------------------------------- |
| (none) | 0         | Phones, designed from 360px        |
| `sm:`  | 640px     | Large phones, landscape            |
| `md:`  | 768px     | Tablets (portrait)                 |
| `lg:`  | 1024px    | Tablets (landscape), small laptops |
| `xl:`  | 1280px    | Desktops                           |
| `2xl:` | 1536px    | Large desktops                     |

Target range: **360px to 1440px**. Above 1440px, content is capped at `max-w-content` and centred.
